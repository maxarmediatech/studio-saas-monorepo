## Ownership

Check-ins are recurring team/organization updates. A check-in type defines cadence and visibility;
users post one check-in per type per period. Check-ins support rich text, threaded comments, and
links to other studio entities.

## Database Shape

| Table | Owns | Notes |
| --- | --- | --- |
| `checkin_types` | Scope, team, name, emoji, description, frequency, scheduled time, active flag, audit, soft delete. | Scope is organization or team. |
| `checkins` | User check-in post, rich-text payload, business date, comment count, audit, soft delete. | One active post per user/type/date. |
| `checkin_comments` | Threaded comments with rich-text payload, parent/root pointers, reply count, soft delete. | Mirrors discussion message threading. |
| `checkin_links` | Links check-ins to studio entities. | Unique per checkin/entity pair. |

Important indexes/constraints:

| Index/constraint | Purpose |
| --- | --- |
| `checkin_types_scope_team_constraint` | Team scope requires `teamId`; organization scope requires no `teamId`. |
| `checkin_types_org_idx` | Organization list/filter. |
| `checkin_types_team_idx` | Team-scoped lookup. |
| `checkins_type_user_date_unique` | One active check-in per user, type, and period date. |
| `checkins_type_date_idx` | List check-ins by type/date. |
| `checkins_user_date_idx` | User/crew check-in history. |
| `checkin_comments_thread_idx` | Thread reply list. |
| `checkin_links_entity_idx` | Find linked entity check-ins. |

Enums:

- scope: `organization`, `team`
- frequency: `daily`, `weekdays`, `weekly`

Link entity types:

- `booking`
- `shoot`
- `deliverable`
- `task`
- `payment_schedule`

## Read Contracts

`listTypes` accepts:

- `scope`
- `teamId`
- `includeInactive`

Visibility rules:

- owners/admins can view all organization check-ins and team check-ins
- non-admins can view organization-scoped types and team-scoped types for teams they belong to
- inactive types are excluded unless requested

`listCheckins` accepts:

- `checkinTypeId`
- cursor: `checkinDate`, `id`
- `limit`

`getCheckin` returns:

- base check-in fields
- check-in type
- author
- links

`listComments` accepts:

- `checkinId`
- optional `threadRootId`

`listUserCheckins` accepts:

- `userId`
- `dateFrom`
- `dateTo`
- cursor: `checkinDate`, `id`
- `limit`

## Check-in Type Contracts

Create type requires:

- `scope`
- `name`
- `frequency`

Optional:

- `teamId`
- `emoji`
- `description`
- `scheduledTime`

Scope rules:

- `scope = organization`: `teamId` must be omitted; only owner/admin can create or update
- `scope = team`: `teamId` is required; non-admin creator must belong to the team

Update type can change:

- `scope`
- `teamId`
- `name`
- `emoji`
- `description`
- `frequency`
- `scheduledTime`
- `isActive`

Only admins can change visibility or team assignment.

Delete type:

- soft-deletes by setting `deletedAt`/`deletedBy`
- does not physically delete check-ins/comments

## Check-in Post Contracts

Create check-in accepts:

- `checkinTypeId`
- optional `content`
- optional `contentJson`
- optional `checkinDate`
- optional `links`

Date behavior:

- API computes the effective period date from type frequency, scheduled time, and timezone
- timezone preference order: `x-user-timezone` header, user timezone, organization timezone
- weekly check-ins use week start
- weekdays skip weekend dates

Create behavior:

- verifies type visibility/access
- validates linked entities through shared discussion link validator
- builds rich text JSON/text when content is present
- inserts check-in with `createdBy`
- inserts links when provided
- maps duplicate period rows to `CONFLICT`

The schema accepts `checkinDate`, but create currently uses the computed effective period date.

Update check-in:

- owner/admin only
- updates rich-text content fields
- rejects invalid rich-text content

Delete check-in:

- owner/admin only
- soft-deletes post

## Comment Contracts

Create comment requires:

- `checkinId`
- either `content` or `contentJson`

Optional:

- `parentId`

Behavior:

- verifies check-in access
- validates parent belongs to same check-in
- sets `threadRootId` for replies
- increments check-in `commentCount`
- increments parent/root reply count for replies

Update/delete:

- comment author only
- update rebuilds rich-text payload
- delete soft-deletes and decrements counts

## Link Contract

Check-in links reuse discussion entity-link validation. The user must have access to the target entity,
and the target row must belong to the active organization and not be deleted.

Links are physically deleted by `removeLink`.

## Change Checklist

When changing check-ins:

- update `packages/api/modules/checkins/schemas.ts`
- update check-in procedures and access/date helpers
- update `packages/database/drizzle/schema/checkins.ts` plus migrations for table/index changes
- update shared rich-text/link validation if payload or link types change
- update team membership/visibility consumers
- update frontend query helpers, check-in pages/forms, and crew detail history
- update this page in the same PR

## Known Gaps

- `createCheckinInputSchema` accepts `checkinDate`, but create uses the computed period date instead.
- Link rows are physically deleted, so link removals have no audit trail.
- Type deletion is soft, but child check-ins/comments remain.
- Rich metadata/search behavior depends on `contentText`; consumers should not parse rich-text JSON for previews.
