## Ownership

Saved views store reusable table state for studio entity lists. A view belongs to an entity type and
can capture filters, display filter labels, column visibility, sorting, styling, public/private
visibility, and per-user favorites.

## API Operations

All saved view procedures use `studioProtectedProcedure` and active organization scope.

| Operation | Method/path | Input schema | Output schema | Permission | Notes |
| --- | --- | --- | --- | --- | --- |
| `savedViews.list` | `GET /saved-views` | `listSavedViewsInputSchema` | `listSavedViewsOutputSchema` | mapped entity `list` | Lists public views and current user's private views. |
| `savedViews.create` | `POST /saved-views` | `createSavedViewInputSchema` | `createSavedViewOutputSchema` | mapped entity `create` | Creates custom non-system view. |
| `savedViews.update` | `PUT /saved-views/{id}` | `updateSavedViewInputSchema` | `updateSavedViewOutputSchema` | mapped entity `update` | Updates owner/private or public view. |
| `savedViews.delete` | `DELETE /saved-views/{id}` | `deleteSavedViewInputSchema` | `deleteSavedViewOutputSchema` | mapped entity `delete` | Physically deletes owner-created non-system view. |
| `savedViews.toggleFavorite` | `POST /saved-views/{viewId}/favorite` | `toggleFavoriteInputSchema` | `toggleFavoriteOutputSchema` | mapped entity `list` | Inserts or deletes favorite row. |

## Read Contracts

`list` accepts:

- `entityType`

Returns:

- view identity and owner
- `entityType`
- `name`, `description`, `icon`, `color`
- `filters`
- `displayFilters`
- `columnVisibility`
- `sorting`
- `isSystem`, `isDefault`, `isPublic`
- `sortOrder`
- timestamps
- `isFavorite`
- `createdByUser`

List behavior:

- requires list permission for requested entity type
- excludes system views
- returns public views plus views created by current user
- orders by `sortOrder`, then `name`
- computes `isFavorite` from current user's favorite rows

## Create Contract

Required fields:

- `entityType`
- `name`

Optional fields:

- `description`
- `icon`
- `color`
- `filters`
- `displayFilters`
- `columnVisibility`
- `sorting`
- `isPublic`

Create behavior:

- requires create permission for mapped resource
- sets `createdBy` to current user
- stores empty `{}` filters by default
- sets `isSystem = false`, `isDefault = false`
- sets `sortOrder = 100`

## Update/Delete Contract

Update can change:

- `name`
- `description`
- `icon`
- `color`
- `filters`
- `displayFilters`
- `columnVisibility`
- `sorting`
- `isPublic`

Update behavior:

- checks user is authorized for at least one entity type with update permission
- scopes lookup to active organization and authorized entity types
- rejects system views
- allows owner updates
- allows updates to public views even if current user is not the creator

Delete behavior:

- scopes lookup to active organization and authorized entity types
- rejects system views
- requires current user to be creator
- physically deletes `saved_views`; favorite rows cascade

Favorite behavior:

- scopes lookup to active organization and authorized entity types
- if favorite exists, deletes it and returns `isFavorite: false`
- otherwise inserts favorite and returns `isFavorite: true`

## Change Checklist

When changing saved views:

- update `packages/api/modules/studio/schemas/saved-view.ts`
- update permission mapping when adding entity types
- update DB schema/migrations for persisted table state changes
- update frontend filter/table hooks that apply `filters`, `displayFilters`, `columnVisibility`, or `sorting`
- add or adjust regression tests for permission scoping
- update this page in the same PR

## Known Gaps

- `saved_views` has no soft delete.
- `saved_views_org_entity_name_idx` makes names unique across public and private views for the same entity type.
- System/default view flags exist, but list currently excludes system views.
- Public view update is allowed for non-creators if they have update permission for that entity type.
- Filter payloads are generic JSON and validated by consumers, not centrally by entity type.
