## Ownership

Invoices represent billable documents for bookings. They can be created directly from line items or
generated from a payment schedule. Invoice totals are cached on the invoice row and recalculated when
line items change.

| Area | Source |
| --- | --- |
| Router | `packages/api/modules/invoices/router.ts` |
| Procedures | `packages/api/modules/invoices/procedures/*.ts` |
| Contract schemas | `packages/api/modules/studio/schemas/invoice.ts` |
| Helpers | `packages/api/modules/invoices/lib/*` |

| Receipt helpers | `packages/api/modules/receipts/lib/receipt-helpers.ts` |

## Database Shape

| Table | Owns | Notes |
| --- | --- | --- |
| `invoices` | Header, status, dates, totals, linked booking/schedule, audit, soft delete. | Active invoice numbers are unique per organization. |
| `invoice_line_items` | Line item type, description, quantity, unit price, amount, sort order. | Physically deleted when removed. |
| `payment_schedules` | Optional source schedule for invoice generation. | One invoice per active schedule is enforced in API. |
| `received_amounts` | Payments can link to invoices. | Drives paid amount/status updates. |
| `receipts` | Receipt evidence for invoice payments. | Generated by payment flows. |

Important constraints:

| Constraint/index | Purpose |
| --- | --- |
| `invoices_org_number_idx` | Active invoice number unique per organization. |
| `invoices_paid_amount_range` | Paid amount must be between zero and total. |
| `invoice_line_items_itemized_check` | `item`/`service` require quantity and unit price; amount equals quantity times unit price. |
| `invoice_line_items_lump_sum_check` | `milestone`/`expense` use amount only. |

Enums:

- invoice status: `draft`, `sent`, `paid`, `partial`, `overdue`, `cancelled`
- line item type: `milestone`, `item`, `service`, `expense`
- tax type: `exclusive`, `inclusive`, `no_gst`

## API Operations

All invoice procedures use `studioProtectedProcedure` and active organization scope.

| Operation | Method/path | Input schema | Output schema | Permission | Notes |
| --- | --- | --- | --- | --- | --- |
| `invoices.list` | `GET /invoices` | `listInvoicesInputSchema` | `listInvoicesOutputSchema` | `payment:list` | Paginated list with booking/client info. |
| `invoices.get` | `GET /invoices/{id}` | `getInvoiceInputSchema` | `getInvoiceOutputSchema` | `payment:read` | Detail with booking, client, line items, schedule. |
| `invoices.create` | `POST /invoices` | `createInvoiceInputSchema` | `createInvoiceOutputSchema` | `payment:create` | Creates draft invoice and line items. |
| `invoices.createFromSchedule` | `POST /invoices/from-schedule` | `createInvoiceFromScheduleInputSchema` | `createInvoiceFromScheduleOutputSchema` | `payment:create` | Creates draft invoice for one unpaid schedule. |
| `invoices.update` | `PUT /invoices/{id}` | `updateInvoiceInputSchema` | `updateInvoiceOutputSchema` | `payment:update` | Updates draft/sent unpaid invoice fields. |
| `invoices.markSent` | `POST /invoices/{id}/send` | `markInvoiceSentInputSchema` | `markInvoiceSentOutputSchema` | `payment:update` | Draft to sent with sent timestamp. |
| `invoices.cancel` | `POST /invoices/{id}/cancel` | `cancelInvoiceInputSchema` | `cancelInvoiceOutputSchema` | `payment:update` | Cancels draft/sent/overdue invoices with no paid amount. |
| `invoices.delete` | `DELETE /invoices/{id}` | `deleteInvoiceInputSchema` | `deleteInvoiceOutputSchema` | `payment:delete` | Soft delete only if no payments. |
| `invoices.addLineItem` | `POST /invoices/{invoiceId}/line-items` | `addLineItemInputSchema` | `addLineItemOutputSchema` | `payment:update` | Draft invoices only. |
| `invoices.updateLineItem` | `PUT /invoices/line-items/{id}` | `updateLineItemInputSchema` | `updateLineItemOutputSchema` | `payment:update` | Draft invoices only. |
| `invoices.removeLineItem` | `DELETE /invoices/line-items/{id}` | `removeLineItemInputSchema` | `removeLineItemOutputSchema` | `payment:update` | Draft invoices only; cannot remove last item. |

## Read Contracts

`list` accepts:

- `bookingId`
- `clientId`
- `status`
- `dateFrom`, `dateTo`
- `amountMin`, `amountMax`
- `search`
- pagination, sorting, and `includeDeleted`

`list` returns base invoice fields plus:

- `bookingName`
- `bookingReferenceNumber`
- `clientName`

`get` returns:

- base invoice fields
- `booking`: `id`, `name`, `referenceNumber`
- `client`: `id`, `name`, `email` when found
- `lineItems`
- `schedule`: `id`, `name`, `amount`, `dueDate` when linked

## Create Contract

Direct create requires:

- `bookingId`
- `issueDate`
- at least one `lineItems` entry

Optional fields:

- `dueDate`
- `notes`
- `terms`
- `discountAmount`
- `taxType`

Line item rules:

- `item`/`service`: require `quantity` and `unitPrice`; server computes `amount`
- `milestone`/`expense`: require `amount`; `quantity` and `unitPrice` are not allowed

Create behavior:

- verifies booking belongs to active organization and is not deleted
- generates organization-scoped invoice number
- calculates subtotal/tax/discount/total
- creates draft invoice and all line items in one transaction
- tracks non-blocking invoice activity

## Schedule Generation Contract

`createFromSchedule`:

- verifies schedule belongs to active organization and is not deleted
- rejects partial, completed, or cancelled schedules
- rejects if an active invoice already exists for the schedule
- creates a draft invoice with one milestone line item for the schedule amount
- links `invoices.paymentScheduleId`

## Update And Status Contract

Invoice fields editable through `update`:

- `issueDate`
- `dueDate`
- `notes`
- `terms`
- `discountAmount`
- `taxType`

Only draft or sent invoices with `paidAmount = 0` are editable.

Status transitions:

- `markSent`: draft to sent
- payment helpers: sent/partial to partial or paid based on `received_amounts`
- `cancel`: draft, sent, or overdue to cancelled when unpaid

Line item changes:

- only allowed while invoice is draft
- recalculate invoice totals after add/update/remove
- remove rejects deleting the last line item

Delete behavior:

- soft-deletes the invoice
- rejects invoices with payments; cancel instead
- line items remain because the invoice is soft-deleted

## Related Surfaces

| Surface | Relationship |
| --- | --- |
| Payments | Received payments can link to invoices and update invoice status. |
| Receipts | Invoice-linked payments generate receipts. |
| Payment schedules | Schedules can create invoices and receive converted payments. |
| Bookings | Invoice belongs to booking and uses booking/client context. |
| Global search | Invoices are searchable. |

## Change Checklist

When changing invoice behavior:

- update `packages/api/modules/studio/schemas/invoice.ts`
- update invoice procedures and route metadata
- update `packages/api/modules/invoices/lib/*` when totals, numbering, or statuses change
- update DB schema/migration for invoice or line item shape changes
- update payment/receipt helpers if payment status rules change
- update invoice UI, filters, table columns, and exports
- update this page in the same PR

## Known Gaps

- Invoice PDF/email/payment-link endpoints are not present yet.
- `delete` leaves line items in place because invoice deletion is soft.
- Receipt/payment edits after invoice payment may not fully resync historical receipt display.
- `createFromScheduleInputSchema` defines `dueDate` twice; runtime behavior is harmless but the schema should be cleaned.
- Invoice line item remove uses physical delete, unlike invoice header soft delete.
