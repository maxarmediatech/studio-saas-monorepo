## What Deployments Own

Deployment docs explain how code moves from this monorepo into running services, what checks should pass, and how to recover when a rollout breaks.

The repo currently contains:

- a Vercel-linked web project in local `.vercel/project.json`
- a Fumadocs handbook app at `apps/handbook`
- Dockerfiles for WhatsApp bridge and worker services
- GitHub PR validation for lint and web E2E
- Turborepo build orchestration

There is no tracked `vercel.json` and no deploy workflow in `.github/workflows`. Treat deployment automation as provider-owned until a tracked workflow is added.

## Build Commands

```bash
pnpm build
pnpm build:all
pnpm handbook:build
```

Root script behavior:

- `pnpm build`: builds the web app and its dependencies through Turborepo
- `pnpm build:all`: builds every buildable package
- `pnpm handbook:build`: builds the handbook and its dependencies
- `pnpm start`: starts the Turborepo start task

`turbo.json` declares build outputs:

- `dist/**`
- `.next/**`
- excludes `.next/cache/**`

The web package build uses:

```bash
NODE_OPTIONS='--max-old-space-size=4096' next build
```

The handbook build uses:

```bash
next build
```

## PR Validation

Pull requests to `main` run `.github/workflows/validate-prs.yml`.

Jobs:

- `lint`: `biome ci .`
- `e2e`: installs dependencies, runs `pnpm --filter database generate`, runs `pnpm env:check`, runs `pnpm --filter web e2e:ci`, uploads the Playwright report

CI environment:

```dotenv
DATABASE_URL=
BETTER_AUTH_SECRET=
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

The current PR workflow does not run every local gate. For broad changes, run:

```bash
pnpm typecheck
pnpm build:all
```

## Release Checklist

Before merging a web or shared-package change:

```bash
pnpm lint
pnpm check
pnpm typecheck
pnpm build
```

Before merging a handbook change:

```bash
pnpm handbook:typecheck
pnpm handbook:build
```

Before merging a database migration:

```bash
pnpm db:generate
pnpm db:migrate
pnpm typecheck
```

Before merging a worker change:

```bash
pnpm --filter @repo/sms-worker test
pnpm --filter @repo/calendar-worker test
pnpm typecheck
```

Pick the relevant subset for the changed area, but do not skip local verification for deploy-affecting changes just because PR CI is narrower.

## Environment Requirements

Core web deploys need:

```dotenv
DATABASE_URL=
BETTER_AUTH_SECRET=
NEXT_PUBLIC_SITE_URL=
```

Feature-specific deploys need provider groups from [Environment](/docs/operations/environment):

- auth/OAuth for social login and calendar integrations
- Resend for transactional mail
- MSG91 for SMS
- Dodo Payments for checkout and webhooks
- S3-compatible storage for uploads
- analytics public variables for tracking

Workers need their provider variables plus database access. Do not assume the web project environment automatically exists for independently deployed workers.

## Rollback

For Vercel-hosted apps, rollback through the Vercel deployment history or CLI for the linked project.

Local verification before rollback decision:

```bash
pnpm build
pnpm env:check
```

Rollback is usually correct when:

- a deploy introduces auth outage
- checkout or webhooks stop processing
- migrations are not compatible with the running app
- route rendering fails for a large user-facing surface

Rollback is not enough when:

- a migration already changed production data
- a webhook provider retried and duplicated state
- a worker is still processing bad queued jobs
- an environment secret is wrong

In those cases, stop the affected worker or provider callback first, then decide whether to rollback code.

## Post-Deploy Smoke Checks

Web:

- home page loads
- sign-in flow reaches auth provider or email flow
- dashboard/studio route access works for a known account
- upload policy route works when storage is enabled
- checkout starts when payments are enabled

Handbook:

- `/docs` loads
- key architecture pages render
- search/navigation works
- no MDX build warnings

Workers:

- process starts without missing env errors
- queue count decreases
- failed count does not spike
- provider success rate is healthy
- retry behavior matches the runbook

## Failed Deploy Triage

1. Read the failing build log and copy the exact error.
2. Reproduce with the matching local command.
3. Run `pnpm env:check` for core env failures.
4. Run the package type check for TypeScript failures.
5. Inspect migration output for database failures.
6. Check provider secrets only in the deployment provider, not in git.
7. Verify the fix with the same command that failed.

For GitHub workflow failures, use:

```bash
gh run list
gh run view
```

For Vercel failures, inspect the deployment log for the linked project and then reproduce with the matching pnpm script.
